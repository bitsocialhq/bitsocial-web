# چالش ووچر

چالش ووچر انتشار محتوا را پشت کدهای ووچر یکتایی قرار می‌دهد که مالک جامعه توزیع می‌کند. به‌جای تکیه بر امتیازدهی خودکار، اعتماد را به یک جریان دعوت دستی منتقل می‌کند که در آن افراد شناخته‌شده کدها را از کانالی دریافت می‌کنند که مالک کنترلش می‌کند.

- **کد منبع و README فعلی:** [github.com/bitsocialnet/voucher-challenge](https://github.com/bitsocialnet/voucher-challenge#readme)
- **بسته‌ی npm:** [`@bitsocial/voucher-challenge`](https://www.npmjs.com/package/@bitsocial/voucher-challenge)

## نصب

```bash
npm install @bitsocial/voucher-challenge
```

## چطور کار می‌کند

1. مالک جامعه یک یا چند کد ووچر یکتا تولید می‌کند.
2. مالک آن کدها را از راه کانالی که خودش انتخاب می‌کند (پیام مستقیم، ایمیل، حضوری و مانند آن) به نویسندگان مورد اعتماد می‌رساند.
3. وقتی نویسنده‌ای تلاش می‌کند مطلبی منتشر کند، سامانه‌ی چالش از او کد ووچر می‌خواهد.
4. کد اعتبارسنجی می‌شود — اگر معتبر باشد و پیش‌تر استفاده نشده باشد، انتشار پذیرفته می‌شود.

هر کد ووچر پس از استفاده به یک نویسنده‌ی مشخص گره می‌خورد و دیگران نمی‌توانند دوباره از آن استفاده کنند.

## مرجع فعلی بسته

این صفحه عمداً یک مرور کلی است، نه بازتابی از راهنمای راه‌اندازی. README بسته منبع حقیقت برای نام‌های فعلی چالش‌ها، نمونه‌های Bitsocial CLI، ثبت در pkc-js، گزینه‌های پشتیبانی‌شده و رفتار مصرف کد است:

- [README مربوط به Voucher Challenge](https://github.com/bitsocialnet/voucher-challenge#readme)

هنگام پیکربندی یک جامعه‌ی زنده، README بالادستی را ترجیح دهید، چون گزینه‌های ووچر و مسیرهای نصب همراه با خود آن بسته نسخه‌بندی می‌شوند، نه همراه با این وب‌سایت.

## چه زمانی از آن استفاده کنیم

چالش ووچر بیش از همه برای این موارد مناسب است:

- **جوامع فقط با دعوت** که عضویت در آن‌ها عمداً محدود است.
- **فضاهای گزیده** که مالک شخصاً هر شرکت‌کننده را بررسی می‌کند.
- **محیط‌های پراعتماد** که در آن‌ها امتیازدهی خودکار اسپم لازم یا مطلوب نیست.

چون به توزیع دستی کد نیاز دارد، برای جوامع باز و بزرگ مقیاس‌پذیر نیست. برای آن سناریوها به‌جای این گزینه [مسدود کننده اسپم](./spam-blocker.md) یا [چالش فراخوانی قرارداد EVM](./evm-contract-call.md) را در نظر بگیرید.

# నైపుణ్యాలు మరియు సాధనాలు

నైపుణ్యాలను, బాహ్య సాధనాలను సెటప్ చేసేటప్పుడు లేదా సర్దుబాటు చేసేటప్పుడు ఈ ప్లేబుక్‌ను వాడండి.

## సిఫార్సు చేసిన నైపుణ్యాలు

### Playwright CLI

బ్రౌజర్ ఆటోమేషన్ (నావిగేషన్, ఇంటరాక్షన్, స్క్రీన్‌షాట్‌లు, పరీక్షలు, డేటా వెలికితీత) కోసం `playwright-cli` వాడండి.

రెపో UI ధృవీకరణ కోసం `playwright-cli` వాడుతున్నప్పుడు ఒక ఇంజిన్‌తోనే ఆపవద్దు. సంబంధిత ఫ్లోను మూడు ప్రధాన బ్రౌజర్ ఇంజిన్‌లలోనూ అమలు చేయండి:

- Blink కోసం `chrome`
- Gecko కోసం `firefox`
- Safari/WebKit కవరేజ్ కోసం `webkit`

ఆధారాలు వేరువేరుగా ఉండేలా ప్రతి ఇంజిన్‌కు పేరున్న ప్రత్యేక సెషన్‌లను వాడండి, కానీ ఆ సెషన్‌లను ఒకదాని తర్వాత ఒకటి నడపండి. యంత్రం మొత్తంలో ఒకేసారి ఒక Playwright బ్రౌజర్ సెషన్ మాత్రమే చురుకుగా ఉండాలి, ఎందుకంటే ఇక్కడ పోటీ పడే వనరు రిపాజిటరీ కాదు, యంత్రం RAM మరియు CPU. సెషన్‌లను `./scripts/pw-session.sh` ద్వారానే తెరవండి, మూసివేయండి; అది ఆ భాగస్వామ్య లాక్‌ను పట్టుకుంటుంది కాబట్టి సమాంతర ఏజెంట్లు యంత్రాన్ని ఉక్కిరిబిక్కిరి చేయకుండా బ్రౌజర్ పనిని వాయిదా వేసి మళ్లీ ప్రయత్నిస్తాయి. ఏదైనా ఇంజిన్‌ను ఉద్దేశపూర్వకంగా వదిలేస్తే, కారణాన్ని నమోదు చేయండి.

పని జరుగుతున్న దశలో Chrome/Blink మాత్రమే వాడండి. మార్పు తుది ధృవీకరణకు సిద్ధమయ్యాక Chrome, Firefox, WebKit పూర్తి క్రమాన్ని ఒకసారి అమలు చేయండి. ప్రతి ఇంజిన్ సెషన్‌ను పరిమాణం మార్చి డెస్క్‌టాప్‌కు, మొబైల్‌కు తిరిగి వాడండి; తర్వాత దాన్ని తప్పనిసరిగా మూసివేసి, అప్పుడే తదుపరి ఇంజిన్‌ను తెరవండి.

```bash
./scripts/pw-session.sh open verify-chrome https://bitsocial.localhost --browser=chrome
playwright-cli -s=verify-chrome snapshot
./scripts/pw-session.sh close verify-chrome
```

స్లాట్ బిజీగా ఉన్నప్పుడు `open` 75 కోడ్‌తో నిష్క్రమిస్తుంది; చేతితో మళ్లీ మళ్లీ ప్రయత్నించే బదులు `./scripts/pw-session.sh open --wait[=SECONDS] ...` (డిఫాల్ట్ 300 సెకన్లు) మీద వేచి ఉండండి. మధ్యలో ఆగిపోయిన వర్క్‌ఫ్లో వదిలేసిన లాక్ దానంతట అదే విడుదల అవుతుంది, ఎందుకంటే నమోదైన బ్రౌజర్ ఇక నడవని ఏ స్లాట్‌నైనా `open` వదిలేస్తుంది. లాక్ ఎవరి దగ్గర ఉందో `./scripts/pw-session.sh status`తో పరిశీలించండి; బ్రౌజర్ స్థితిని `status` ధృవీకరించలేని అరుదైన సందర్భంలో మాత్రమే చివరి ఉపాయంగా `release <session>` వాడండి.

```bash
npm install -g @playwright/cli@latest
playwright-cli install --skills
```

## MCP విధానం వెనుక కారణం

ఈ ప్రాజెక్ట్‌లో GitHub MCP మరియు బ్రౌజర్ MCP సర్వర్‌లను వాడవద్దు; అవి టూల్-స్కీమా, కాంటెక్స్ట్ పరంగా గణనీయమైన భారాన్ని జోడిస్తాయి.

- GitHub కార్యకలాపాలు: `gh` CLI వాడండి.
- బ్రౌజర్ కార్యకలాపాలు: `playwright-cli` వాడండి.

## మోడల్ లభ్యత

- `composer-2` కేవలం Cursorలో మాత్రమే అందుబాటులో ఉంది. దాన్ని `.claude/` లేదా `.codex/` కింద కాన్ఫిగర్ చేయవద్దు.
- Codex `latest` అనే మోడల్ అలియాస్‌ను డాక్యుమెంట్ చేయలేదు. `.codex/**/agents/*.toml` కింద కమిట్ చేసిన కస్టమ్-ఏజెంట్ TOML ఫైల్‌లు `model`, `model_reasoning_effort` రెండింటినీ వదిలేస్తాయి, తద్వారా అవి ప్రస్తుత పేరెంట్ సెషన్ సెట్టింగ్‌లను వారసత్వంగా పొందుతాయి.

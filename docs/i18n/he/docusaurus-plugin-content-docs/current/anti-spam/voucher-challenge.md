# אתגר השוברים

Voucher Challenge מתנה פרסום תוכן בקודי שובר ייחודיים שמפיץ בעל הקהילה. במקום להישען על ניקוד אוטומטי, הוא מעביר את האמון לתהליך הזמנה ידני, שבו אנשים מוכרים מקבלים קודים דרך ערוץ שבשליטת הבעלים.

- **קוד מקור ו-README עדכני:** [github.com/bitsocialnet/voucher-challenge](https://github.com/bitsocialnet/voucher-challenge#readme)
- **חבילת npm:** [`@bitsocial/voucher-challenge`](https://www.npmjs.com/package/@bitsocial/voucher-challenge)

## התקנה

```bash
npm install @bitsocial/voucher-challenge
```

## איך זה עובד

1. בעל הקהילה מייצר קוד שובר ייחודי אחד או יותר.
2. הבעלים מפיץ את הקודים למחברים מהימנים דרך ערוץ לבחירתו: הודעה ישירה, אימייל, מסירה אישית וכדומה.
3. כשמחבר מנסה לפרסם, מערכת האתגרים מבקשת ממנו קוד שובר.
4. הקוד עובר אימות — אם הוא אמיתי ועדיין לא נוצל, הפרסום מתקבל.

כל קוד שובר נקשר למחבר מסוים ברגע המימוש, כך שאחרים אינם יכולים להשתמש בו שוב.

## הפניה לחבילה העדכנית

הדף הזה הוא סקירה בכוונה, ולא שכפול של מדריך התקנה. ה-README של החבילה הוא מקור האמת לשמות האתגרים הנוכחיים, לדוגמאות של Bitsocial CLI, לרישום ב-pkc-js, לאפשרויות הנתמכות ולהתנהגות המימוש:

- [README של Voucher Challenge](https://github.com/bitsocialnet/voucher-challenge#readme)

העדיפו את ה-README במקור כשאתם מגדירים קהילה פעילה, מכיוון שאפשרויות השוברים ותהליכי ההתקנה מנוהלים בגרסאות יחד עם החבילה ולא יחד עם האתר הזה.

## מתי להשתמש בו

אתגר השוברים מתאים במיוחד ל:

- **קהילות בהזמנה בלבד** שבהן החברות מוגבלת בכוונה.
- **מרחבים מאוצרים** שבהם הבעלים בודק אישית כל משתתף.
- **סביבות בעלות אמון גבוה** שבהן ניקוד ספאם אוטומטי מיותר או בלתי רצוי.

מכיוון שהוא מחייב הפצת קודים ידנית, הוא אינו מתאים לקהילות פתוחות וגדולות. לתרחישים כאלה, שקלו במקום זאת את [חוסם דואר זבל](./spam-blocker.md) או את [אתגר קריאה לחוזה EVM](./evm-contract-call.md).

# تحدي استدعاء عقد EVM

يتحقق تحدي استدعاء عقد EVM من حالة المؤلف على السلسلة قبل السماح بالنشر. ويستطيع مالكو المجتمعات اشتراط أن تستوفي محفظة أو هوية محلولة شرطًا للقراءة فقط في عقد ذكي، مثل امتلاك حد أدنى من رصيد رمز ما، قبل النشر.

- **الشيفرة المصدرية وملف README الحالي:** [github.com/bitsocialnet/evm-contract-challenge](https://github.com/bitsocialnet/evm-contract-challenge#readme)
- **حزمة npm:** [`@bitsocial/evm-contract-challenge`](https://www.npmjs.com/package/@bitsocial/evm-contract-challenge)

## التثبيت

```bash
npm install @bitsocial/evm-contract-challenge
```

## أين يناسب

استخدم هذا التحدي في المجتمعات التي ينبغي أن تعتمد فيها المشاركة على إشارة خارجية من EVM: ملكية رمز، أو ملكية NFT، أو درجات إثبات الشخصية، أو عضوية في الحوكمة، أو أي شرط آخر يمكن قراءته من عقد.

والتحدي تلقائي من وجهة نظر المؤلف بمجرد إعداده. فهو يفحص مصادر المحافظ أو الهويات المؤهلة، ويستدعي دالة العقد المُعدّة، ثم يقارن القيمة المُعادة بشرط المجتمع.

## مرجع الحزمة الحالي

هذه الصفحة نظرة عامة عن قصد، وليست نسخة مطابقة من مرجع الإعداد. فملف README الخاص بالحزمة هو المرجع الموثوق لأسماء التحديات، وأمثلة Bitsocial CLI، والتسجيل في pkc-js، والقيم الافتراضية للخيارات، وأمثلة ABI، وسلوك RPC، ومصادر المحافظ المدعومة:

- [ملف README الخاص بتحدي عقد EVM](https://github.com/bitsocialnet/evm-contract-challenge#readme)

فضّل الرجوع إلى ملف README الأصلي عند إعداد مجتمع حي، لأن خيارات العقد وأمثلته تُصدَر مع تلك الحزمة لا مع هذا الموقع.

## متى تستخدمه

تحدي استدعاء عقد EVM مثالي في الحالات التالية:

- **المجتمعات المقيَّدة بالرموز** التي تقصر النشر على حاملي الرمز.
- **الوصول المقيَّد بـ NFT** حيث تُشترط ملكية NFT بعينه.
- **مساحات حوكمة DAO** حيث تقتصر المشاركة على حاملي رمز الحوكمة.

أما المجتمعات التي لا تعتمد على الهوية على السلسلة، ففكّر بدلًا من ذلك في [مانع البريد العشوائي](./spam-blocker.md) أو [تحدي القسائم](./voucher-challenge.md).

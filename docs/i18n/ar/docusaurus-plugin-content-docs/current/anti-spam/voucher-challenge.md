# تحدي القسائم

يحصر تحدي القسائم نشر المحتوى خلف رموز قسائم فريدة يوزّعها مالك المجتمع. وبدل الاعتماد على تقييم آلي، ينقل الثقة إلى مسار دعوة يدوي يتلقى فيه أشخاص معروفون رموزًا عبر قناة يتحكم بها المالك.

- **الشيفرة المصدرية وملف README الحالي:** [github.com/bitsocialnet/voucher-challenge](https://github.com/bitsocialnet/voucher-challenge#readme)
- **حزمة npm:** [`@bitsocial/voucher-challenge`](https://www.npmjs.com/package/@bitsocial/voucher-challenge)

## التثبيت

```bash
npm install @bitsocial/voucher-challenge
```

## كيف يعمل

1. يولّد مالك المجتمع رمز قسيمة فريدًا واحدًا أو أكثر.
2. يوزّع المالك تلك الرموز على المؤلفين الموثوقين عبر قناة يختارها (رسالة مباشرة، أو بريد إلكتروني، أو تسليم شخصي، وما إلى ذلك).
3. عندما يحاول مؤلف النشر، يطالبه نظام التحدي برمز قسيمة.
4. يُتحقق من الرمز — فإن كان صحيحًا ولم يُستخدم من قبل، يُقبل المنشور.

يرتبط كل رمز قسيمة بمؤلف بعينه بمجرد استبداله، فيُمنع إعادة استخدامه من قِبَل غيره.

## مرجع الحزمة الحالي

هذه الصفحة نظرة عامة عن قصد، وليست نسخة مطابقة من دليل الإعداد. فملف README الخاص بالحزمة هو المرجع الموثوق لأسماء التحديات الحالية، وأمثلة Bitsocial CLI، والتسجيل في pkc-js، والخيارات المدعومة، وسلوك الاستبدال:

- [ملف README الخاص بتحدي القسائم](https://github.com/bitsocialnet/voucher-challenge#readme)

فضّل الرجوع إلى ملف README الأصلي عند إعداد مجتمع حي، لأن خيارات القسائم ومسارات التثبيت تُصدَر مع تلك الحزمة لا مع هذا الموقع.

## متى تستخدمه

تحدي القسائم هو الأنسب في الحالات التالية:

- **المجتمعات المقتصرة على الدعوات** حيث تكون العضوية مقيّدة عن قصد.
- **المساحات المنتقاة** حيث يفحص المالك كل مشارك بنفسه.
- **البيئات عالية الثقة** حيث يكون التقييم الآلي للبريد العشوائي غير ضروري أو غير مرغوب.

ولأنه يتطلب توزيعًا يدويًا للرموز، فهو لا يتوسع ليناسب المجتمعات المفتوحة الكبيرة. وفي تلك الحالات، فكّر بدلًا من ذلك في [مانع البريد العشوائي](./spam-blocker.md) أو [تحدي استدعاء عقد EVM](./evm-contract-call.md).

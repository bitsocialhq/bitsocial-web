# EVM Contract Call Challenge

EVM Contract Call Challenge проверяет ончейн-состояние автора, прежде чем разрешить публикацию. Владельцы сообществ могут требовать, чтобы кошелёк или связанная с автором идентичность удовлетворяли условию, читаемому из смарт-контракта, — например, держали минимальный баланс токена — и только тогда допускать публикацию.

- **Исходный код и актуальный README:** [github.com/bitsocialnet/evm-contract-challenge](https://github.com/bitsocialnet/evm-contract-challenge#readme)
- **Пакет npm:** [`@bitsocial/evm-contract-challenge`](https://www.npmjs.com/package/@bitsocial/evm-contract-challenge)

## Установка

```bash
npm install @bitsocial/evm-contract-challenge
```

## Где это уместно

Используйте эту проверку в сообществах, где участие должно зависеть от внешнего сигнала EVM: владения токеном, владения NFT, оценки proof-of-personhood, членства в управлении или другого условия, читаемого из контракта.

После настройки для автора всё происходит автоматически. Проверка перебирает подходящие кошельки и источники идентичности, вызывает заданный метод контракта и сравнивает возвращённое значение с условием сообщества.

## Когда её использовать

EVM Contract Call Challenge хорошо подходит для:

- **Сообществ с токен-гейтингом**, где публиковать могут только держатели токена.
- **Доступа по NFT**, где требуется владение конкретным NFT.
- **Пространств управления DAO**, где участие ограничено держателями токена управления.

Сообществам, которые не опираются на ончейн-идентичность, стоит вместо этого посмотреть на [Spam Blocker](./spam-blocker.md) или [Voucher Challenge](./voucher-challenge.md).

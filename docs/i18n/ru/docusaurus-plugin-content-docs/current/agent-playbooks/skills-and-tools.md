### Playwright CLI

Используйте `playwright-cli` для автоматизации браузера (навигация, взаимодействие, снимки экрана, тесты, извлечение данных).

Когда вы применяете `playwright-cli` для проверки UI репозитория, не останавливайтесь на одном движке. Прогоняйте нужный сценарий во всех трёх основных браузерных движках:

- `chrome` для Blink
- `firefox` для Gecko
- `webkit` для покрытия Safari/WebKit

Используйте отдельные именованные сессии для каждого движка, чтобы свидетельства не смешивались, но запускайте эти сессии последовательно. Одновременно на всей машине может быть активна только одна браузерная сессия Playwright, потому что спорный ресурс — это оперативная память и процессор машины, а не репозиторий. Открывайте и закрывайте сессии через `./scripts/pw-session.sh`; он удерживает эту общую блокировку, поэтому параллельные агенты откладывают браузерную работу и повторяют попытку, а не перегружают машину. Если движок пропущен намеренно, зафиксируйте причину.

Во время итераций используйте только Chrome/Blink. Полную последовательность Chrome, Firefox и WebKit прогоняйте один раз, когда изменение готово к финальной проверке. Переиспользуйте сессию каждого движка для десктопа и мобильного, меняя размер окна, закрывайте её в блоке очистки и только затем открывайте следующий движок.

```bash
./scripts/pw-session.sh open verify-chrome https://bitsocial.localhost --browser=chrome
playwright-cli -s=verify-chrome snapshot
./scripts/pw-session.sh close verify-chrome
```

Когда слот занят, `open` завершается с кодом 75; вместо ручных повторов блокируйтесь на `./scripts/pw-session.sh open --wait[=SECONDS] ...` (по умолчанию 300 с). Блокировка, оставшаяся после прерванного процесса, освобождается автоматически, потому что `open` сбрасывает любой слот, чей записанный браузер больше не запущен. Посмотрите текущего владельца через `./scripts/pw-session.sh status`; `release <session>` — крайняя мера для редкого случая, когда `status` не может подтвердить состояние браузера.

```bash
npm install -g @playwright/cli@latest
playwright-cli install --skills
```

Места установки навыка:

- `.cursor/skills/playwright-cli/`
- `.claude/skills/playwright-cli/`

## Обоснование политики по MCP

Избегайте в этом проекте GitHub MCP и браузерных MCP-серверов: они добавляют значительные накладные расходы на схемы инструментов и контекст.

- Операции с GitHub: используйте CLI `gh`.
- Операции с браузером: используйте `playwright-cli`.

## Доступность моделей

- `composer-2` доступна только в Cursor. Не настраивайте её в `.claude/` или `.codex/`.
- Codex не документирует алиас модели `latest`. Закоммиченные TOML-файлы кастомных агентов в `.codex/**/agents/*.toml` опускают и `model`, и `model_reasoning_effort`, чтобы наследовать текущие настройки родительской сессии.

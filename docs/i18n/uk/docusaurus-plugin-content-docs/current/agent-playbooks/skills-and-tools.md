# Навички та інструменти

Використовуйте цей плейбук, коли налаштовуєте або коригуєте навички та зовнішній інструментарій.

## Рекомендовані навички

### Context7 (документація бібліотек)

Для актуальної документації щодо бібліотек.

```bash
npx skills add https://github.com/intellectronica/agent-skills --skill context7
```

### Playwright CLI

Використовуйте `playwright-cli` для автоматизації браузера (навігація, взаємодія, знімки екрана, тести, витяг даних).

Коли ви користуєтеся `playwright-cli` для перевірки UI репозиторію, не зупиняйтеся на одному рушії. Проганяйте відповідний сценарій у всіх трьох основних браузерних рушіях:

- `chrome` для Blink
- `firefox` для Gecko
- `webkit` для покриття Safari/WebKit

Використовуйте окремі іменовані сесії для кожного рушія, щоб докази лишалися ізольованими, але запускайте ці сесії послідовно. Одночасно на всій машині може бути активна лише одна браузерна сесія Playwright, бо конкурентним ресурсом є RAM і CPU машини, а не репозиторій. Відкривайте й закривайте сесії через `./scripts/pw-session.sh`: він тримає цей спільний лок, тож паралельні агенти відкладають і повторюють роботу з браузером, замість того щоб перевантажувати машину. Якщо якийсь рушій свідомо пропущено, запишіть чому.

Під час ітерацій використовуйте лише Chrome/Blink. Повну послідовність Chrome, Firefox і WebKit проганяйте тоді, коли зміна готова до фінальної перевірки. Перевикористовуйте сесію кожного рушія для десктопа й мобільного, змінюючи її розмір, закривайте її в прибиранні на кшталт finally і лише після цього відкривайте наступний рушій.

```bash
./scripts/pw-session.sh open verify-chrome https://bitsocial.localhost --browser=chrome
playwright-cli -s=verify-chrome snapshot
./scripts/pw-session.sh close verify-chrome
```

Коли слот зайнятий, `open` завершується з кодом 75; блокуйтеся на `./scripts/pw-session.sh open --wait[=SECONDS] ...` (типово 300 с) замість того, щоб повторювати спроби вручну. Лок, залишений після перерваного робочого процесу, звільняється автоматично, бо `open` скидає будь-який слот, чий записаний браузер більше не працює. Погляньте, хто тримає лок, через `./scripts/pw-session.sh status`; `release <session>` — це крайній засіб для рідкісного випадку, коли `status` не може підтвердити стан браузера.

```bash
npm install -g @playwright/cli@latest
playwright-cli install --skills
```

Місця встановлення навичок:

- `.cursor/skills/playwright-cli/`
- `.claude/skills/playwright-cli/`

### Найкращі практики React від Vercel

Для глибших рекомендацій щодо продуктивності React/Next.

```bash
npx skills add https://github.com/vercel-labs/agent-skills --skill vercel-react-best-practices
```

### Пошук навичок

Знаходьте та встановлюйте навички з відкритої екосистеми.

```bash
npx skills add https://github.com/vercel-labs/skills --skill find-skills
```

## Обґрунтування політики щодо MCP

Уникайте GitHub MCP і браузерних MCP-серверів у цьому проєкті, бо вони додають значні накладні витрати на схеми інструментів і контекст.

- Операції з GitHub: використовуйте `gh` CLI.
- Операції з браузером: використовуйте `playwright-cli`.

## Доступність моделей

- `composer-2` доступний лише в Cursor. Не налаштовуйте його в `.claude/` чи `.codex/`.
- Codex не документує аліас моделі `latest`. Закомічені TOML-файли кастомних агентів у `.codex/**/agents/*.toml` пропускають і `model`, і `model_reasoning_effort`, тож вони успадковують поточні налаштування батьківської сесії.
